## 1. 当前架构

```
2.0TP 触摸屏 ──(12P 排线)── STM32F407_SHIELD1 ── STM32F407VET6
                                                    │
                                        板间 I²C（PB8/PB9 ↔ ECW IO24/IO23）
                                                    │
ECW6700F（YL6700B）: MIC 接口 + 背面 SPI SD 卡槽 + Wi-Fi 天线
```

- **ECW6700F**：PDM 麦克风 32kHz 采集 → PCM16 **8kHz** 单声道（4:1 低通抽取）→ SD 裸扇区环形区持续写入（16KB/s）；
  收到 STM32 的触发后取最近 `APP_CLIP_SECONDS` 秒，按当前 HTTP 契约上传；
  另支持喇叭回放最近 N 秒（STM32 发 `0x03`，采集暂停，播完恢复）。
- **STM32F407**：只做触摸事件桥。CST816D 按下沿 → I²C1 主机写 1 字节命令给 ECW（从机 0x42）。

### 1.1 数据流

```
PDM 麦克风 → I2S 32kHz → 4:1 低通抽取 PCM16LE 8kHz → SD 环形区（约 16KB/s）
触摸（I2C 0x42 收到 0x01）→ 快照最近 N 秒 → 上传队列 → HTTP POST
STM32 写 0x03 → ECW 暂停采集 → I2S TX 回放最近 N 秒 → 恢复采集
```

### 1.2 板间命令

| 命令 | 值 | 方向 | 含义 |
|---|---|---|---|
| `LINK_EVT_TOUCH` | 0x01 | STM32 → ECW | 触摸，取最近 N 秒并上传 |
| `LINK_EVT_PING` | 0x02 | STM32 → ECW | 上电心跳（预留） |
| `LINK_EVT_PLAY` | 0x03 | STM32 → ECW | 喇叭回放最近 N 秒（回放期间采集暂停） |

### 1.3 ECW 源文件

| 文件 | 作用 |
|---|---|
| `main.c` | 任务编排：采集 / 触发 / 上传 / 网络；上传队列深度 4 |
| `app_config.h` | Wi-Fi、服务器、N 秒、全部引脚宏 |
| `app_audio.c` | I2S PDM 采集；三级 64 抽头 + 64:1 抽取 + DC blocker |
| `app_sdspi.c` | **GPIO 位翻转软件 SPI** 模式 SD（CMD0/8/55/41/58/16/9/17/24 + CRC7/CRC16） |
| `app_store.c` | 从 LBA 2048 起的裸扇区环形区（上限 512MB），4KB 写、跨环读取 |
| `app_link.c` | I²C0 从机 0x42；中断回调只置标志，任务上下文读命令 |
| `app_playback.c` | 暂停采集 → I²S TX 回放最近 N 秒 → 恢复采集 |
| `app_net.c` | Wi-Fi STA + AP 扫描诊断 + lwip socket + HTTP POST |

## 2. 已确认的引脚

### 2.1 STM32F407（经 SHIELD1 / expansion-20260915）

| 信号 | 引脚 | 说明 |
|---|---|---|
| 触摸 I2C_SCL | PA8 | I2C3，7 位地址 0x15（HAL 8 位 0x2A） |
| 触摸 I2C_SDA | PC9 | I2C3 |
| T_RES | PD15 | 低有效，低 10ms → 高 200ms |
| T_INT | PD10 | 输入上拉，当前轮询不使用 |
| BLK（背光/模组使能） | PD14 | 高有效，启动时拉高 |
| S_RES（LCD 复位） | PA11 | 高有效 |
| LCD CS / DC | PC11 / PC13 | 输出高 |
| LCD SPI_SCK / MOSI | PC10 / PC12 | AF6 SPI3（当前只上电，不驱动画面） |
| 板间 I²C | PB8 / PB9 | I2C1 主机，目标 7 位 0x42（HAL 8 位 0x84） |
| 调试串口 | PB10 / PB11 | USART3，115200 8N1 |

### 2.2 ECW6700F

| 信号 | IO | 说明 |
|---|---|---|
| MIC WS / SCK / SD | IO6 / IO7 / IO8 | PDM；SCK 约 2.048MHz；IO3 未接，配为 MCLK |
| SD CS / SCK / MISO / MOSI | IO11 / IO14 / IO12 / IO13 | **软件 SPI**，非硬件 SPI 外设 |
| 板间 I²C SCL / SDA | IO24 / IO23 | I2C0 从机，7 位地址 0x42 |

> 板上的拨动开关只切换 CH340 接到哪块板的 UART（ECW 或 STM32）；板间 I²C 不受影响。

## 4. 构建与烧录

### 4.1 ECW6700F

工程路径含中文时，SDK make 的 `realpath` 会失败。需要 ASCII 目录联接：

```powershell
New-Item -ItemType Junction -Path 'C:\moce' -Target 'E:\博一 资料\黑客松\逆向开发'
```

```bash
cd /c/moce
# 默认构建 firmware-code-ff5c7de034b6-ecw6700
bash ecw-build-output/build_firmware.sh

# 或直接构建仓库版本（含 app_playback）
MOCE_PROJECT="/c/moce/desk-pet/ecw6700" bash ecw-build-output/build_firmware.sh
# 产物：ecw-build-output/firmware_allinone.bin / firmware_cpu.bin / firmware.elf / firmware.map
```

构建脚本会：
1. 复用/解包固定版本 SDK（B02P12）；
2. 应用 Windows makefile 补丁；
3. 在 SDK 启动文件中插入 `moce_app_main()`，并**注释掉 `local_ota_main()`**（关键，见第 5 节）；
4. 把 `main/*.c` + `board_support` 接入 `Boards/ecw6700f/standalone`；
5. 用 ESWIN GCC 14.1.1 构建并导出镜像。

烧录（开关拨到 `ECW6700/ESP32` 一侧）：

```bash
cd C:/moce/MOCEWorkbench-data/moce-cache-ca0b65ff70a4/flash-jobs
C:/moce/MOCEWorkbench-data/tools/ecw6700-windows/flash/eswin_tool.exe \
  flash --device COM7 --allinoneFile C:/moce/ecw-build-output/firmware_allinone.bin
```

ECW 只有 RST 键，没有 BOOT 键；`eswin_tool` 通过 CH340 的 RTS 脉冲进入 ROM 下载模式。
烧录完成后 `chip start_up` 自动重启，串口 115200 8N1 看日志。

### 4.2 STM32F407

```bash
cd /c/moce
bash firmware-code-5a2b43165fb8-stm32f407/build_firmware.sh
# 或 desk-pet/stm32f407/build_firmware.sh
```

脚本会在 `C:\temp\armgcc` 建立指向**工具链根目录**的目录联接（GCC 用相对路径找 cc1/libgcc，
必须是根目录而不是 bin），构建目录放在 `C:\temp\moce_stm32_build`。

进入 Bootloader（关键）：
- BOOT0 = 1、BOOT1 = 0；
- **在 BOOT0 保持高电平期间**按复位或断电重上电（按一下 BOOT0 就松手再复位是无效的）；
- 串口 115200 **8E1**（偶校验），写 `firmware.bin` 到 `0x08000000`；
- 烧完 BOOT0 = 0，复位运行。

可用 MOCE Workbench 的 `backend/stm32_uart.py` 做带身份校验的烧录（芯片 ID 0x413、512KB、
UID 校验、逐字节回读）。

## 5. 关键修复与踩坑记录

### 5.1 SDK SPI1 的 CPU 全双工 RX 晚 1 bit → 改用软件 SPI

- 现象：CMD0 返回 0x00（应为 0x01），CMD8 的 R7 从 `00 00 01 AA` 变成 `00 00 00 D5`
  （整段右移 1 bit）。
- 尝试：mode 0 有响应但偏移；mode 1/2/3 全部 0xFF；DMA 全双工对短传输无响应；
  `RX_TX` 调度会卡死。
- 解决：`app_sdspi.c` 改为 **GPIO 位翻转软件 SPI**（`bb_byte`），时序完全可控；
  实测约 0.5–1MHz，64KB/s 录音够用。
- 可用映射：**CS=IO11、SCK=IO14、MOSI=IO13、MISO=IO12**；代码仍保留 4 种映射自动尝试，
  日志会打印哪种命中。

### 5.2 SDK local OTA 把 WPA supplicant 卡死

- 现象：`[wpa-W] Pending scan scheduled, reject new request`、
  `[wifi_ctrl-E] can not scan fac wifi`，之后所有扫描/连接失败。
- 原因：`CONFIG_OTA_LOCAL` 的 `local_ota_main()` 启动时扫描 `local_ota_test`。
- 解决：构建脚本在启动文件中注释掉 `local_ota_main()`（幂等正则，只匹配行首原始调用）。

### 5.3 `HAL_I2C_DeInit()` 会关 I2C 时钟，`HAL_I2C_Init()` 不会重新开

总线恢复后必须 `__HAL_RCC_I2Cx_CLK_ENABLE()` 再 `HAL_I2C_Init()`，否则扫描会卡住。

### 5.4 AP 扫描诊断

`app_net.c` 的 `net_scan_debug()` 在 STA stop 后做一次非阻塞扫描并打印实际 SSID/信道/RSSI。
排查 Wi-Fi 时先看这份列表：能看到目标 SSID 才说明射频/天线正常。

### 5.5 2.0TP 模组上电

只复位触摸 PD15 不够：需要先把 PA11（LCD 复位）拉高、PD14（背光/使能）拉高，
模组才完全上电。之前一块 2.0TP 屏损坏，表现为 I²C 扫描“每个地址都 ACK”的总线假象；
换屏后恢复。

### 5.6 SD 卡与触点

- SD 卡没插紧时 CMD0 返回 0xFF；上电第一次初始化可能因卡未就绪失败，应用每 2 秒重试会恢复。
- 裸扇区写入从 LBA 2048 开始，会覆盖卡上原有文件系统；测试卡不要放其他数据。

### 5.7 Wi-Fi 频段

部分手机热点接入新设备后会自动从 2.4GHz 切到 5GHz，ECW 会断连或扫描不到。
联调时固定热点为 **2.4GHz**。曾用临时热点 `moce/12345678` 验证通过。

### 5.8 STM32 进入 Bootloader

必须“BOOT0 高电平期间复位/上电”；按一下 BOOT0 再复位是无效的。

### 5.9 构建脚本幂等性

启动文件补丁必须只匹配“行首空白 + 原始调用”的行；否则会把已注释的行再次替换成
嵌套注释（`/* /* ... */ ... */`），编译报 `"/*" within comment`。

## 6. 服务器通信现状

当前固件实现的是**可配置明文 HTTP**（`app_net.c`）：

1. `POST /api/record`：JSON 记录事件（含 `clip_id`、秒数、字节数、采样率）。
2. `POST /api/audio`：WAV（44 字节头 + PCM16LE 单声道 8kHz 落盘；正式协议会升采样到 16kHz），body 从 SD 环形区流式读取。
3. 只有 HTTP 2xx 才算成功，失败重试 2 次；`X-Clip-Id` 可用于服务端幂等去重。

> 服务器侧的正式协议见仓库外/服务器侧的 `HARDWARE_INTEGRATION.md`（`desk-recorder/v1`）：
> **MQTT 3.1.1+TLS（8883）+ HTTPS（443）**、App 发起保存任务、16kHz/单声道/16-bit WAV、
> UTC 校时、SHA256、`GET/POST/PUT/result` 四步上传、任务持久化与重启恢复。
> 这套协议与当前明文 HTTP 实现**不兼容**；当前阶段按需求保持软硬件逻辑不变，
> 服务器通信改造暂缓。接入前需要：
> - 设备凭据（`device_id`、`device_token`、MQTT 用户名/密码、`ca.crt`）；
> - 服务端开放 443/8883、服务监听 `0.0.0.0`；
> - 音频改为 16kHz、保留时长改为分钟级（1–60，默认 10）；
> - 增加 UTC 校时（SNTP/RTC）、SHA256、任务持久化。
>
> 另注：该协议不允许设备自行创建保存任务（只能 App/管理网页创建），
> “触摸屏拍一下保存”需要服务端扩展或经 App 中转，接入前需先定产品流程。

## 7. 安全注意

公开仓库 `ecw6700/main/app_config.h` 当前包含真实 Wi-Fi 凭据和服务器地址，且已存在于
git 历史（初始提交 `34aca69`）。**仅修改文件不能消除历史泄露**，请优先：

1. 修改手机热点密码（使泄露凭据失效）；
2. 如服务器地址/端口也不宜公开，考虑更换或限制访问；
3. 后续可把 `app_config.h` 改为占位符（`YOUR_WIFI_SSID` / `YOUR_WIFI_PASSWORD` /
   `YOUR_SERVER_IP`），但历史仍保留旧值。

已从公开仓库排除的内容：编译产物（`.bin/.elf/.hex/.map`、`build/`，ECW 镜像的 `.rodata`
中含真实 Wi-Fi 凭据）、厂商数据手册 PDF、含密码的 zip。

## 8. 已知限制与后续建议

- **音频内容**未验证：建议导出 WAV 或让服务器保存，确认不是静音/噪声；异常时优先查
  PDM 时钟（IO7）、数据（IO8）、WS/SCK 是否反。
- **喇叭回放**未实机试听：确认 I2S TX 引脚、音量衰减（`APP_PLAYBACK_VOLUME_DIV`）和
  采集暂停/恢复时序。
- **服务器**：先修可达性/端口，再决定是否迁移到 `desk-recorder/v1`；当前 HTTP 契约保留。
- **软件 SPI 吞吐**：当前约 0.5–1MHz；提高采样率/双声道前需评估总线占用，或向 ESWIN
  确认硬件 SPI 的采样时序。
- **上传队列**深度 4：连续快速触摸会丢；可按产品语义增大或只保留最后一次。
- **无 RTC/墙钟**：`clip_id` 是自增计数；接入正式服务器前需补 UTC 时间。
- **无看门狗**：任务卡死只能断电。
- **`叫声音效/` 资产**：当前未被代码引用；`app_playback` 回放的是刚录制的片段，
  不是这些情绪音效。如要做情绪音效播放，需要另行定义触发方式和存放位置。
